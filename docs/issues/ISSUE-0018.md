# ISSUE-0018: 一般ユーザー向けクイズ体験UIを実装する

## 背景
バックエンドには認証、クイズ一覧・詳細、回答・採点、ランキングの各APIが実装済みだが、フロントエンドは管理画面とサービス状況表示が中心で、一般ユーザーがクイズを遊べる導線が未整備だった。

Vercelデプロイ基盤の整備後に公開サービスとして操作確認できるよう、一般向けのMVP画面をAPIへ接続する。

## 目的
- 新規登録・ログインからクイズ回答までの導線をブラウザ上で成立させる。
- クイズ検索、詳細、採点結果、ランキングを既存APIへ接続する。
- 管理画面と一般画面のエントリーポイントを分離する。
- ローディング、空状態、エラー状態を含む利用可能なMVP UIを提供する。

## 対応範囲
- `/`: ホーム
- `/signup`: 新規登録
- `/login`: ログイン
- `/quizzes`: 一覧・検索・カテゴリ絞り込み・ページング
- `/quizzes/:id`: 詳細・回答・採点結果
- `/rankings`: 総合ランキング
- `/quizzes/:id/rankings`: クイズ別ランキング
- JWTセッション管理
- レスポンシブUI
- README / Issue文書 / Qiita下書き

## 設計

### エントリーポイント分離
`frontend/src/main.jsx` で初期パスを判定する。

- `/admin*` と `/status`: 既存の `App`
- その他: 新規の `PublicQuizApp`

これにより既存の管理画面実装を変更せず、一般向け機能を独立して追加する。

### 認証セッション
MVPでは以下を `localStorage` に保存する。

- `quizverse_access_token`
- `quizverse_user`

起動時に `GET /api/auth/me` でセッションを確認する。401応答時は保存済み認証情報を削除する。

> 仮置き: 本番向けのCookieベース認証やrefresh tokenは本Issueの対象外とする。

### APIクライアント
`frontend/src/public/api.js` に以下を集約する。

- JSONリクエスト
- Authorizationヘッダー
- エラーレスポンス変換
- 401時のセッションクリア
- 認証 / クイズ / 採点 / ランキングAPI

### 回答仕様
- 選択済み問題のみ `answers` に含める。
- 未回答はバックエンド仕様に従い `skipped` として採点する。
- 正答判定はサーバー側で行い、プレイ前のレスポンスから正答を推測しない。
